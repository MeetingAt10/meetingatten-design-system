### M3. Treatments tier, strict Tailwind, `check:tokens`

Treatment tokens (v0.3.0 set). Tiles need no new tokens: the semantic `bg`/`fg` pairs already fit (LIGHT: `secondary` and `accent` 50/800, `info` 50/source-blue; DARK: all three 950/300).

| Token | Light | Dark |
|---|---|---|
| `card-bg` | `{color.surface}` | `{color.raised}` |
| `card-shadow` | `{shadow.elevation-1}` | `none` |
| `card-shadow-hover` | `{shadow.elevation-2}` | `none` |
| `card-highlight` | `none` | inset top 1px, `{color.neutral.dark-border}` at 40% to transparent |
| `card-highlight-hover` | `none` | same at 60% |
| `overlay-shadow` | `{shadow.elevation-2}` | `{shadow.elevation-2}` + `card-highlight` |
| `wash-accent` | `{color.accent.100}` to transparent, closest-side radial | `{color.accent.950}` to transparent |
| `wash-secondary` | `{color.secondary.100}` to transparent | `{color.secondary.950}` to transparent |
| `wash-info` | `{color.info.50}` to transparent | `{color.info.950}` to transparent |
| `lift` (shared) | `-2px` | `-2px` |
| `radius-card` / `-tile` / `-control` / `-chip` (shared) | `{radius.12}` / `{radius.8}` / `{radius.6}` / `{radius.4}` | same |

- Treatments use a small structured grammar, not free CSS strings (`{ "wash": { "from": "{color.accent.100}" } }`, `{ "highlight": { "color": "…", "alpha": 40 } }`). `build.mjs` emits the CSS (`radial-gradient(closest-side, var(--ds-accent-100), transparent)`, `color-mix(in srgb, … 40%, transparent)`).
- Contrast pairs: `tokens/contrast-pairs.json` gains a treatments section that resolves each wash's `from` stop per theme and checks `text-primary`, `text-secondary`, `action-default` on it (4.5). Measured worst case today: `text-secondary` on `accent-100` = 6.14:1 (light); dark worst is `action-default` on `secondary-950` = 7.15:1.
- `check:tokens` (new, plain Node), wired into `npm run check`, fails on:
  1. Color literals (`#hex`, `rgb(`, `hsl(`, `oklch(`, named colors other than `transparent`/`currentColor`) in `src/css/**`, `src/react/**`, `site/**` (excluding generated files).
  2. Any `var(--ds-<primitive>)` (brand, neutral, success, warning, danger, info, secondary or accent followed by a step) in `src/css/**`, `src/react/**`, `site/**`. Only semantic, treatment, dimension, type, space, size, motion and z tokens are allowed.
  3. Treatment values that reference anything other than locked `{color.*}`, `{shadow.*}`, `{radius.*}`, `{motion.*}`, `transparent` or `none`.
- `dist/tailwind.css`: `--color-*: initial;` first; colors = semantic only; `--shadow-card`, `--shadow-card-hover`, `--shadow-overlay`; `--radius-card|tile|control|chip`; `@utility wash-accent|wash-secondary|wash-info`. Removed: primitive color utilities, `ink`, `ink-secondary`, `line`, `--radius-overlay` (now equal to `card`) (**BREAKING**).
- `parity.mjs`: treatments listed as REPO-OWNED; still 0 problems against Figma.
- Verify: `npm run check` exits 0; seeding a hex into a scratch CSS file makes `check:tokens` exit 1; `grep -c "neutral-500" dist/tailwind.css` = 0.

### M4. CSS split, then restyle

Two separate PRs so the refactor can be checked for "no visual change" before the look changes.

- **M4a split (no visual change):** move `src/components.css` into `src/css/base/*.css` and `src/css/components/<category>/<name>.css` (categories match `components/<category>/*.md`). Native nesting. `--ds-ring` (and `--ds-ring-inset` for selected states) replaces the repeated box-shadow recipe. Hardcoded sizes become tokens (`.ds-eyebrow`, spinner). `build.mjs` concatenates into `dist/components.css` inside `@layer ds.base, ds.components;`. State selector convention for every state: native pseudo-class + React Aria attribute + forced class, e.g. `&:is(:hover, [data-hovered], .is-hover)`, `&:is(:active, [data-pressed], .is-pressed)`, `&:is(:focus-visible, [data-focus-visible], .is-focus)`. Verify: screenshots of `preview/index.html` and all templates in light and dark match the pre-split screenshots.
- **M4b restyle (soft layers):** cards use `card-bg`, `card-shadow`, `card-highlight`, no border by default; interactive cards (`a.ds-card`, `.ds-card[data-interactive]`) lift by `lift` and step to `card-shadow-hover` over `motion-duration-base`; with `prefers-reduced-motion: reduce`, only the shadow changes. Radius remap per the table. Washes available as `.ds-wash` + `--wash` modifier classes. Uniform across all components, Reports included.
- Verify: `npm run check`; light/dark screenshots attached to the PR; no `.ds-card` nested in `.ds-card` in any template.

### M5. React layer scaffolding

- `package.json`: `peerDependencies` `react` and `react-dom` `^19`; `dependencies` `react-aria-components` (exact pin, latest 1.x at implementation time); `devDependencies` `typescript`, `@types/react`, `@types/react-dom`, `vitest`, `jsdom`, `@testing-library/react`, `@testing-library/user-event`, `axe-core` (or `vitest-axe`).
- `exports`: add `"./react": { "types": "./dist/react/index.d.ts", "import": "./dist/react/index.js" }` and `"./react/*"`. No `prepare` script, ever: git installs must not trigger a build.
- `tsconfig.react.json`: `jsx: react-jsx`, `module`/`moduleResolution: NodeNext` (explicit `.js` import extensions), `declaration: true`, `rootDir: src/react`, `outDir: dist/react`. Script `build:react` = `tsc -p tsconfig.react.json`; `npm run build` runs it.
- Components render `ds-*` classes only; they never import CSS (apps import `dist/components.css` once). Interactive components start with `"use client"`; static ones (`Card`, `Badge`, `Container`, …) stay server-safe.
- Test harness: `npm test` = `vitest run`; shared helper renders a component in each state and asserts zero axe violations.
- Verify: `pcore npm run build` emits `dist/react/**` with `"use client"` intact in interactive files; `pcore npm test` passes on a sample `Button`.
